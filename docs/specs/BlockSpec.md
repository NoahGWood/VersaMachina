# BlockSpec Schema (Draft)

BlockSpec defines a modular, machine-readable format for automotive electronic modules (ECUs, sensors, PDMs, switches, etc.).

The format is YAML-based and designed for clarity and extensibility.

---

# 1. Basic Structure

```yaml
id: vendor:module_id
name: Human-Readable Name
version: 1.0.0

tags:
  domain: body
  safety: B

ports:
  - id: batt+
    name: Battery +12V
    kind: Power
    tags:
      voltage: 12
      max_current: 25A

signals:
  provides:
    - id: LampOutputStatus
      type: bool
      source_port: lamp_out

  requires:
    - id: TurnSignalLeft
      type: bool
      via_port: can0
```

------

# 2. Required Fields

### `id`

Unique identifier: `vendor:module_name`.

### `name`

Human-friendly name.

### `version`

Semantic version (`major.minor.patch`).

### `ports`

List of electrical or logical connectors.

**Port fields:**

- `id`
- `name`
- `kind` (Power, Ground, CAN, LIN, I/O, Sensor, PWM, etc.)
- `tags` (voltage, current, bitrate, pullup, etc.)

### `signals`

Logical inputs/outputs associated with ports.

- `provides`: signals generated by this block
- `requires`: signals consumed by this block

------

# 3. Optional Sections

### `fuses`

Tags for associating ports with fuse circuits.

### `grounds`

Tags for identifying required grounding nodes.

### `troubleshooting`

Generic patterns describing symptoms, checks, and possible causes.
 (These are expanded dynamically based on vehicle graphs.)

------

# 4. Validation Rules

- Every port ID must be unique.
- Signal references must point to valid ports.
- Version must follow semver.
- Unknown fields emit warnings but do not invalidate the spec.
